# Polybot — торговый бот для 15-минутных рынков BTC на Polymarket с управлением через Telegram

`polybot/` — самостоятельный бот, собранный на основе этого репозитория. Стратегия и
сигнальные процессоры те же, что в `bot.py`, но бот работает напрямую с API Polymarket,
без NautilusTrader, monkey-патчей и Redis. Ставится одной командой и запускается на Linux,
macOS, Windows или в Docker.

> ⚠️ Торговля на Polymarket — это риск потери денег. По умолчанию бот работает
> в **бумажном режиме**: настоящие ордера не отправляются. Сначала погоняйте его так
> несколько дней и посмотрите на статистику (`/stats`).

## Что делает бот

Каждые 15 минут Polymarket открывает рынок «Bitcoin Up or Down»: Up выигрывает, если
к концу интервала BTC (по Chainlink) не ниже, чем в начале. Бот:

1. Каждые 5 секунд читает стакан Up и копит историю цены текущего рынка.
2. На 13-й минуте (секунды 780–840) смотрит на цену Up:
   - выше `0.60` → покупает **Up**;
   - ниже `0.40` → покупает **Down**;
   - между ними → пропускает рынок (там исход почти монетка).
3. Перед сделкой прогоняет шесть сигнальных процессоров из `core/strategy_brain`
   (стакан, скорость цены, всплески, спот-моментум Coinbase, Fear & Greed, put/call ratio
   Deribit) и объединяет их движком слияния. Как сигналы влияют на сделку, задаёт
   `SIGNAL_FILTER` (см. ниже).
4. Не платит больше `MAX_ENTRY_PRICE` (0.95) за акцию: при цене 0.97 выигрыш даёт 3 цента,
   а проигрыш стоит доллар.
5. Через 1–2 минуты после закрытия рынка узнаёт результат и считает P&L.

Одна сделка на рынок, $1 по умолчанию. Если за UTC-сутки реализованный убыток достиг
`MAX_DAILY_LOSS_USD`, новые сделки до конца суток не открываются.

### Чем бумажная торговля отличается от старой

В `bot.py` результат бумажной сделки выбирался `random.uniform(...)`, поэтому
статистика ничего не говорила о стратегии. Здесь бумажная сделка:

- исполняется по **реальному стакану** в момент решения: бот проходит по ценам продавцов
  на нужную сумму и не выходит за предельную цену;
- платит **реальную комиссию** Polymarket для крипто-рынков: `акции × 0.07 × p × (1 − p)`;
- рассчитывается по **настоящему итогу рынка**: выигрыш $1 за акцию или ноль.

## Установка

Нужен Python 3.10+.

```bash
git clone <этот репозиторий>
cd Polymarket-BTC-15-Minute-Trading-Bot
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements-bot.txt
cp .env.example .env              # Windows: copy .env.example .env
```

Проверьте, что всё доступно:

```bash
python -m polybot check
```

Команда покажет текущий рынок и цены, доступность Coinbase и Fear & Greed, работу
Telegram-токена и готовность ключей для реальной торговли.

## Telegram

1. Создайте бота у [@BotFather](https://t.me/BotFather) командой `/newbot` и скопируйте токен.
2. Впишите токен в `.env`: `TELEGRAM_BOT_TOKEN=123456:ABC...`
3. Запустите бота (`python -m polybot run`) и напишите ему `/start`. Он ответит вашим `chat_id`.
4. Впишите его в `.env`: `TELEGRAM_CHAT_ID=123456789` (несколько через запятую) и перезапустите бота.

Командами управляют только чаты из `TELEGRAM_CHAT_ID`. Остальным бот отвечает только их `chat_id`.

| Команда    | Что делает |
|------------|------------|
| `/status`  | текущий рынок, bid/ask Up, сколько до окна входа, последнее решение, P&L за сегодня |
| `/signals` | сигналы процессоров прямо сейчас и что бот сделал бы, будь сейчас окно входа |
| `/stats`   | сделки, win rate, P&L, комиссии — отдельно для paper и live |
| `/trades`  | последние 10 сделок |
| `/pause`   | не открывать новые сделки (открытые всё равно будут рассчитаны) |
| `/resume`  | продолжить торговлю |

Бот сам пишет, когда запустился, открыл сделку, получил итог рынка, когда нет связи
с Polymarket и когда сработал дневной лимит. С `NOTIFY_SKIPS=true` он также сообщает о
пропущенных рынках.

## Запуск

```bash
python -m polybot run            # бумажная торговля
python -m polybot stats          # статистика в терминале
python -m polybot run --live     # РЕАЛЬНЫЕ ордера
```

Журнал сделок лежит в SQLite `data/polybot.db`, логи пишутся в `logs/polybot.log`.
После перезапуска бот продолжает с того же места: открытые сделки рассчитываются,
пауза сохраняется, по рынку с уже открытой сделкой второй ордер не уйдёт.

### Docker

```bash
cp .env.example .env    # заполните
docker compose up -d --build
docker compose logs -f
```

Для реальной торговли поменяйте в `docker-compose.yml` строку `command` на `["run", "--live"]`.

## Реальная торговля

Заполните в `.env`:

- `POLYMARKET_PK` — приватный ключ кошелька, который подписывает ордера;
- `POLYMARKET_SIGNATURE_TYPE` — `1`, если вы входите на Polymarket по email (Magic);
  `2` — через браузерный кошелёк (MetaMask и т.п.); `0` — обычный EOA-кошелёк;
- `POLYMARKET_FUNDER` — адрес вашего Polymarket-кошелька (на сайте: профиль → адрес
  для депозита). Для типа `0` не нужен.

API-ключи (`POLYMARKET_API_KEY` и т.д.) можно не указывать: бот получит их из приватного ключа.

В live-режиме бот отправляет **fill-or-kill** рыночный ордер на покупку с предельной ценой
`лучший ask + SLIPPAGE` (но не выше `MAX_ENTRY_PRICE`). Если Polymarket ордер отклонил,
бот попробует ещё раз на следующем тике, максимум `MAX_ATTEMPTS_PER_MARKET` раз. Если
непонятно, исполнился ли ордер (обрыв сети во время отправки), бот **не повторяет**
ордер и присылает в Telegram предупреждение — проверьте позиции на сайте.

P&L live-сделок в журнале бота — оценка: комиссию списывает сам Polymarket, а бот вычитает
её по формуле, поэтому может немного занижать результат. Точные цифры смотрите на сайте.

Выигравшие акции Polymarket не обменивает на USDC сам: забирайте выплаты кнопкой
**Claim** в Portfolio на polymarket.com. Статистику бот считает и без этого.

## Настройки

Все параметры с описанием есть в `.env.example`. Главные:

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `TRADE_SIZE_USD` | `1.0` | сумма одной сделки (минимум $1) |
| `TREND_UP_THRESHOLD` / `TREND_DOWN_THRESHOLD` | `0.60` / `0.40` | границы тренда по цене Up |
| `MAX_ENTRY_PRICE` | `0.95` | максимальная цена за акцию |
| `TRADE_WINDOW_START` / `TRADE_WINDOW_END` | `780` / `840` | окно входа в секундах от начала рынка |
| `SIGNAL_FILTER` | `any` | `none` — только тренд; `any` — нужен хотя бы один сигнал (как в `bot.py`); `agree` — консенсус сигналов должен совпасть с трендом |
| `MAX_DAILY_LOSS_USD` | `10` | дневной лимит убытка, `0` — без лимита |
| `PAPER_FEE_RATE` | `0.07` | ставка taker-комиссии для бумажных сделок |

## Устройство

```text
polybot/
├── __main__.py     # CLI: run / check / stats
├── config.py       # настройки из .env
├── polymarket.py   # Gamma API (поиск рынка, итог) + CLOB (стакан), симуляция исполнения
├── market_data.py  # спот BTC (Coinbase) и Fear & Greed
├── strategy.py     # трендовый фильтр + процессоры и fusion из core/strategy_brain
├── trader.py       # PaperTrader (стакан + комиссия) и LiveTrader (py-clob-client)
├── storage.py      # SQLite-журнал сделок и состояние бота
├── engine.py       # главный цикл, расчёт итогов, команды Telegram
├── telegram.py     # клиент Telegram Bot API (long polling)
└── messages.py     # тексты сообщений
tests/test_polybot.py   # тесты без сети: python -m pytest
```

Заодно исправлен баг в `core/strategy_brain/signal_processors/orderbook_processor.py`: CLOB
отдаёт лучшие цены в **конце** списков, а процессор брал первые 10 уровней, то есть
заявки по 1¢ и 99¢ далеко от рынка. Теперь уровни сортируются от лучшей цены. Это
исправление действует и для `bot.py`.
